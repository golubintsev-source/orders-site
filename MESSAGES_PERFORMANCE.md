# Быстрая загрузка сообщений

Раздел сообщений использует двухфазную загрузку.

## Критический путь

1. Пока загружается список, можно показать локальный снимок. Серверный запрос
   возвращает по одной строке на доступный диалог с последним видимым сообщением
   и счётчиком непрочитанного. Бейдж использует тот же расчёт и получает только итог.
2. Диалог запрашивает до 30 последних видимых сообщений и сразу показывает их.
   При прокрутке вверх история догружается порциями до 50 сообщений. Если
   первая порция целиком помещается на экране, следующая догружается автоматически.

## Фоновое обогащение

После первого кадра параллельно загружаются:

- статусы доставки и прочтения участников групповых чатов;
- справочник имён пользователей;
- связи сообщений с задачами;
- реакции и квитанции доставки/прочтения;
- подписанные URL фотографий.

Поколения загрузки и проверка активного диалога не позволяют запоздавшему ответу
перерисовать уже открытый пользователем чат.

## Supabase

Перед публикацией клиента примените `supabase_chat_summary.sql`. Если функция
ещё отсутствует, клиент использует прежние запросы списка и бейджа.

### Индексы

Один раз выполните `supabase_messages_performance.sql` в Supabase SQL Editor.
Миграция добавляет составные индексы для обоих направлений личной переписки,
непрочитанных сообщений, истории группы и квитанций прочтения.

Без миграции клиентская двухфазная загрузка продолжает работать, но на большой
таблице база может тратить больше времени на поиск последних сообщений.
