# Управление чтениями (пункт 3)

## Границы

`js/read-requests.js` подключён через `global.fetch` клиента Supabase.
Обрабатывает только GET/HEAD к REST таблицам текущего проекта. Auth, Storage,
RPC, сторонние API и операции записи не объединяются и не получают этот таймаут.
Автоповторы PostgREST отключены (`db.retry: false`), включая потенциально опасные
повторы POST. Существующие явные бизнес-операции записи не изменены.

Каждый потребитель имеет собственный таймер 15 секунд, независимо от офлайн-режима.
Он охватывает получение заголовков и тела ответа. При зависании потребитель
получает ошибку; последний ушедший потребитель отменяет сетевой fetch.
Отмена на клиенте не гарантирует остановку уже выполняемого SQL на сервере.
На замороженной iOS-вкладке JS-таймер сможет сработать после возобновления JS.

Объединяются только одновременно выполняющиеся одинаковые чтения. Ключ включает
URL (фильтры и сортировку), метод, все заголовки (включая пользователя, схему,
диапазон, формат ответа и count), параметры fetch и поколение записей.
Ключи не журналируются. Каждый потребитель получает собственный Response.
Готовые ответы не кэшируются. Начало и окончание записи отделяют новые чтения
от предыдущего снимка данных; после ошибки/таймаута следующий вызов идёт в сеть.

## Отмена устаревших загрузок

Именованные области загрузки связаны с выходом из раздела и повторной загрузкой:
заказы (включая зависимости отчётов), расчёты, все зарплаты, излишки, задачи,
все изменения, баланс, обе статистики, выбор зарплаты менеджера, диалог чата
и опрос новых сообщений. Для чата также учитывается смена собеседника.
Сигнал передаётся в `abortSignal` PostgREST и в постраничные/пакетные чтения.
Проверки актуальности остаются после await: поздний ответ не перерисовывает новый
экран. Отменённая пагинация возвращает ошибку, а не частичный успешный результат.
Общие справочники и независимые фоновые счётчики не отменяются при смене раздела;
на их REST-чтения распространяются таймаут и объединение.
Внешние картографические запросы, Auth и загрузка файлов — отдельные механизмы.

## Проверки

`npm run test:read-requests`: независимые потребители и тела Response, изоляция
пользователей/фильтров/заголовков, отмена последнего потребителя, зависшее тело,
сетевые и HTTP ошибки, отсутствие кэша, границы записей, отмена пагинации.
Интеграционный тест использует поставляемый с сайтом Supabase JS 2.112.3 и настоящий
локальный HTTP-сервер, включая задержанные/зависшие ответы и операции записи
только в тестовый сервер (не в базу).
Существующие тесты расчётов используют настоящие области отмены и проверяют гонки.

Живая read-only HEAD-проба из среды разработки не завершилась за 5 секунд:
получена контролируемая TimeoutError. Это проверяет ограничение ожидания,
но не подтверждает доступность БД или работу авторизованного интерфейса.
Браузерная проверка/iPhone PWA не выполнена; ускорение на реальной сети не измерено.
